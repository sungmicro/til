# 비교숙련도 분석 프로그램

KOLAS 미생물 시험실의 시험자 간 비교숙련도를 통계 분석하고 보고서를 만든다.
ISO 22196 항균활성과 먹는물 일반세균(중온·저온) 두 가지를 다룬다.

## 구성

| 경로 | 언어 | 용도 |
|---|---|---|
| `R/proficiency.R` | R (base only) | 통계 분석 함수 |
| `R/allocate.R` | R (base only) | 사전 배정기 + 설계 검증 |
| `allocate.py` | Python (표준 라이브러리만) | 사전 배정기 + 설계 검증 |
| `R/report.Rmd` | R Markdown | 보고서 템플릿 |
| `R/render_report.R` | R | Word(.docx) 렌더링 CLI |
| `cfu_stats.py` | Python (표준 라이브러리만) | 통계 코어 |
| `judge.py` | Python | 판정기 CLI (Markdown 출력) |
| `samples/` | CSV | 예시 자료 (분석자 익명화) |
| `tests/` | Python | 테스트 50개 |

R 과 Python 두 언어로 독립 구현하고 `tests/test_cross_language.py` 로 서로 대조한다.
두 구현이 소수 10자리까지 일치해야 테스트가 통과한다.

## 사전 배정 (모드 A — 시험 *전*)

```bash
python3 allocate.py --analysts A,B,C,D,E --samples 1,2,3 --reps 2 --spares 2 \
  --seed 20260914 --sigma-within 0.2835 --delta 0.25 \
  --csv-out out/allocation.csv --template-out out/results_template.csv
```

배정표, 배지 라벨용 CSV, 측정 후 그대로 판정기에 넣을 빈 결과표를 만든다.
`--seed` 를 기록해두면 배정을 언제든 재현할 수 있다.

### 균형 보장

순환 라틴 구성을 쓴다. 시험자 i, 순서 c 의 시료는 `samples[(offset_i + c) mod ns]` 다.
이 구성은 두 균형을 **구성 자체로** 보장한다.

- **행 균형**: 각 시험자가 각 시료를 정확히 `reps` 개 받는다
- **열 균형**: 각 순서의 시료 분포가 `floor(k/ns)` ~ `ceil(k/ns)` 로 고르다

무작위 재시작 탐색이나 단순 회전으로는 보장되지 않는다 (시험자 수가 주기의
배수가 아니면 한 순서에 시료가 몰릴 수 있다). Python·R 양쪽에서 시험자 2~10명,
시료 1~5종, 반복 1~4회의 모든 조합을 검사해 실패 0회를 확인했다.

### 사전 설계 검증

`--sigma-within` 을 주면 시험 **전에** "이 설계로 판정이 성립하는가"를
몬테카를로로 계산한다. 시험자 간 편향이 전혀 없다고 가정했을 때의 통과율이다.

작년 실측 재현성으로 계산한 결과다.

| 균주 | σ_w | 반복 6개일 때 동등성 입증률 (δ=±0.25) | 80% 달성 최소 반복수 | 반복 6개로 입증 가능한 δ |
|---|---|---|---|---|
| E. coli | 0.139 | 35.8% | 10개 | ±0.35 |
| S. aureus | 0.284 | **0.0%** | 39개 | ±0.74 |

S. aureus 는 반복 6개로 ±0.25 동등성을 **원천적으로 입증할 수 없다.**
δ 는 통과할 때까지 늘리는 값이 아니라 적합성 목적에 따라 규정하는 값이므로,
규정값과 달성 가능한 값이 벌어지면 답은 반복수를 늘리거나 시험 기법을
개선하는 것이다.

## 보고서 만들기 (주 용도)

```bash
cd R
Rscript render_report.R \
  --csv ../samples/antibacterial_R_saureus.csv \
  --strain "황색포도상구균 (Staphylococcus aureus)" \
  --atcc "ATCC 6538P" --lot "8923" \
  --out ../out/saureus.docx
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--csv` | (필수) | 입력 CSV |
| `--out` | `<csv>.docx` | 출력 Word 파일 |
| `--type` | `r` | `r`=항균활성 R(변환 없음), `cfu`=집락수(log10 변환) |
| `--delta` | `0.25` | 동등성 한계 (log 단위) |
| `--alpha` | `0.05` | 유의수준 |
| `--sigma` | (없음) | 절차서에 규정된 목표 재현성 σ. 주지 않으면 참가자 자료에서 추정 |
| `--assigned` | (없음) | 기준값. 주지 않으면 참가자 자료에서 추정 |
| `--trials` | `10000` | 무작위 재배정 진단 시행 횟수 |
| `--strain` `--atcc` `--lot` `--method` | - | 보고서 머리말에 들어갈 시험 정보 |

## 입력 형식

첫 열은 시험자명, 나머지 열은 측정값. 열 이름은 숫자여도 된다.

```csv
분석자,1,2,3,4,5,6
A,-0.14,-0.12,-0.04,-0.06,0.06,0.12
B,0.28,0.22,0.19,0.14,-0.06,-0.16
```

**단위를 틀리면 안 된다.** ISO 22196 의 R 은 이미 log 단위라 `--type r` 로 넣어야 한다.
원 집락수만 `--type cfu` 로 넣고, 이때만 log10 변환한다.

## 보고서 구성

1~4장은 기존 Minitab 보고서와 같은 구조이고, 5~8장이 추가된 부분이다.

| 장 | 내용 | 역할 |
|---|---|---|
| 1~2 | 시험 개요, 시험 결과 표 | 기존과 동일 |
| 3 | 등분산 검정 (Levene, 중앙값 중심) | 기존과 동일 |
| 4 | 일원 분산분석 | 기존과 동일 |
| 5 | **z-score 판정 (ISO/IEC 17043)** | 숙련도 합격 여부의 **주 판정** |
| 6 | **동등성 검정 (TOST)** | "차이 없음"의 실제 입증 |
| 7 | **이상치 검정 (Grubbs)** | 값을 제외할 근거가 있는지 |
| 8 | **무작위 재배정 진단** | 탈락 원인이 산포인지 편향인지 구분 |
| 9 | 종합 결론 | |

## 운영 규칙

- **분산분석은 숙련도 합격·불합격 판정 도구가 아니다.** 차이를 탐지하는 검정이므로
  p > 0.05 는 "차이를 찾지 못했다"는 뜻이지 "차이가 없다"는 증명이 아니다.
  합격 판정은 z-score(5장), 차이 없음의 입증은 TOST(6장)가 맡는다.
- **σ 는 절차서에 미리 규정하는 것이 원칙이다.** 참가자 자료에서 추정하면
  순환논리가 되고, 참가자가 적으면 로버스트 추정이 불안정하다. `--sigma` 로 넘길 것.
- **이상치 제외는 Grubbs 검정을 통과한 경우에만.** 눈에 띈다는 이유로 빼면 안 된다.
- **배정은 시험 전에 정하고 기록한다.** 결과를 보고 배정을 고르면 실재하는
  시험자 간 편향을 은폐하게 되고, ISO/IEC 17025 기록 요구사항에도 어긋난다.
- **실명은 저장소에 넣지 않는다.** 비교숙련도 결과는 개인 업무 평가로 읽힐 수 있다.
  시험자는 A~E 로 익명화하고 대응표는 랩 내부 기록으로만 관리한다.

## 설치

R 만 있으면 분석은 돌아간다 (base R 만 사용). Word 출력에는 `rmarkdown` 과
pandoc 이 추가로 필요하며, **RStudio 를 설치하면 pandoc 이 함께 들어온다.**

```r
install.packages("rmarkdown")
```

Python 쪽은 표준 라이브러리만 쓰므로 별도 설치가 필요 없다.

```bash
python3 judge.py samples/antibacterial_R_ecoli.csv --type r   # Markdown 보고서
python3 -m unittest discover -s tests                          # 테스트 50개
```
